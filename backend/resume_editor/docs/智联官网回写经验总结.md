# 智联招聘官网简历回写经验总结（2026-08）

> 继 BOSS（拦截 token + fetch 回放）、猎聘（pusher + 模块勾选）、51job（页面内 resumeApi 直调）之后的第四个真实回写平台。
> 脚本：`backend/resume_editor/platforms/zhilian_write_back.py`

## 一、技术路线：dispatch 官网 Vuex 官方 action（与前三家都不同）

智联简历中心是 Vue2 + Vuex，数据挂在 `#root.__vue__.$store.state.resume.currentResume`。
直接打 HTTP 保存端点行不通：明文端点 `analysisv2/save` 缺加密参数恒 500；真实保存走
`encrypt-key → node-encrypt` 加密流（axios 拦截器注入 at/rt/x-zp-* 头）。最可靠的路线是
**在页面上下文 dispatch 官网自己的 Vuex action**，加密/鉴权/store 刷新全部由官网代码完成：

```js
var store = document.querySelector('#root').__vue__.$store;
store.dispatch('resume/updateResumeAction', {lang, resumeId, resumeNumber, nodeName, values});
store.dispatch('resume/deleteResumeAction', {lang, resumeId, resumeNumber, nodeName, path});
```

- action 返回 `true/false`；成功后 store 自动刷新，逐 op 间隔 1.2s 等刷新再执行下一条
- payload 结构：`{lang, resumeId, resumeNumber, nodeName, values}`；`values.path=null` 新增、有值更新
- resumeId/resumeNumber/lang 从 `store.state.resume.resumeList[resumeIndex]` / `store.state.resume.lang` 取

### 已标定端点（apiDomain=https://fe-api.zhaopin.com，仅供参考，实测不要直调保存）

| 操作 | 方法 | 端点 |
|---|---|---|
| 保存（明文，勿直调） | POST | `/c/i/resume/analysisv2/save`（500） |
| 保存（官方 action 实际走） | POST | `/c/i/resume/encrypt-key` + `/c/i/resume/node-encrypt` |
| 删除 | GET | `/c/i/resume/node/delete?resumeId&resumeNumber&nodeName&lang&path` |
| 证书批量 | POST | `https://cgate.zhaopin.com/resumeapi/resumeCertification/saveCertificationList`，载荷 `{resumeNumber, resumeLanguage, certificationList:[{certificationName, certificationType}], platform:13}`，成功判定 `statusCode==200 && data.success` |

### 各模块 nodeName 与 values 键（bundle 逆向所得，见 zhilian_write_back.py NODE_CFG）

WorkExperience(18 键 pick) / EducationExperience(11) / TrainExperience(5) / LanguageSkill(5，特殊构造) /
ProfessionalSkill(6，特殊构造) / SelfEvaluate(4) / UnifiedPurpose(10，求职意向) / ProjectExperience(透传整对象) /
Certificate(走批量接口，不走 node 保存)。

### 不可用/放弃

- basic_info HARD_SKIP：手机/邮箱为官网脱敏值；基本信息独立保存流未标定

## 二、关键坑

1. **path 漂移**：条目 path 形如 `Resume[3].WorkExperience[2]`，删除一条后其余索引漂移。
   执行时逐 op 从最新 store 按 hintPath/业务键重新定位目标，不能一次性生成全部 op 的 path。
2. **自我评价 500 字上限**：超限保存静默失败（action 返回 false，无报错）。脚本 `SELF_EVAL_MAX_LEN=500` 截断守卫。
3. **「至今」表示**：endDate=0 + endDateFormat='1970/01/01 08:00:00'（官网占位值，实测）。
4. **bundle 逆向方法**：页面内 fetch CDN JS 被 CORS 拦 → curl 直接下载 resume.web.js/chunk-common.js 本地正则提取。
5. **bash 双引号吞 `$store`**：`python -c "...__vue__.$store..."` 中 `$store` 被 shell 变量替换成空 → JS 探针一律写成 .py 文件执行。
6. **Vuex dump 拿不到 action 源码**：store._actions 全是 dispatch 包装器 → 必须走 bundle grep 或钩 XHR/fetch 捕获真实请求。
7. **macOS 代理**：同 51job，子进程必须注入 `NO_PROXY=127.0.0.1,localhost`。

## 三、回写策略

- 数据源：`zhilian_writeback.json` 快照（writeback-save 端点生成）优先，回退 `zhilian_fields.json`
- 模块：self_evaluation / wanna / work_experience / education / projects / training / language / skill_tags / certificates（basic_info HARD_SKIP）
- 语义：**全量覆盖** —— path 精确匹配（回退业务键前 3 键匹配）→ edit；本地多出 → add（`values.path=None` 强制清理陈旧 path）；官网多余 → del；no-op 短路
- certificates 特殊：整列表比对（certUserdefName+certDateFormat 排序集合），不同则整批 replace
- 复核：回写后重新拉 store，按业务键匹配 + 条数比对

## 四、接入方式

- CLI：`python zhilian_write_back.py [--dry-run] [--json] [--paths work_experience,education]`，输出 `RESULT_JSON:` 标记行
- `/api/agent-map/write-back`：`{platform:"zhilian", dry_run, paths}`（WRITE_BACK_SCRIPTS 映射）
- `/api/unified/sync-back`：与猎聘/51job 同模式（SNAPSHOT_PLATFORMS，读快照、传 --paths）
- 前端 `zhilian-tab.tsx`：顶部 sticky「智联模块回写」操作条 + 映射报告卡（仿 51job-tab，主色 #2A7BFF）；回写成功后不调 onRefresh
