# 飞书接入新手手册（从零到 ping 通）

> 目标：从零开始，让本系统与你的飞书完全打通——多维表格当数据中枢、群里 @机器人 下指令、战报自动推送。
> 预计耗时 10~15 分钟（大部分时间在飞书开放平台上点选）。
>
> 配套入口：
> - 配置填写页面：前端「策略实验室 → 系统底层配置」（所有密钥在页面填写即可，保存即时生效）
> - 配置验证：配置页「飞书」分组 → **「检测连通性」按钮**（一键体检，失败项会告诉你怎么修）

---

## 0. 先认值：整个接入 = 拿齐 5 个值 + 做对 3 处授权

原理一图流（为什么不需要公网 IP、为什么表格能双向同步）：

```
┌──────────────────────────┐
│ 飞书开放平台（你的自建应用）│
│  ├─ 机器人能力            │
│  ├─ im:message 权限       │
│  ├─ bitable 读写权限      │
│  └─ 事件订阅（长连接）     │
└────────┬─────────────────┘
         │ App ID + App Secret
         ▼
┌──────────────────────────┐     WebSocket 长连接（无需公网 IP）
│ 本系统后端 uvicorn:8000   │ ◄──── 群消息事件下行
│  ├─ 飞书 WS 客户端        │ ────► 回复卡片 / 战报推送
│  └─ Bitable 读写客户端 ───┼────► 多维表格（岗位/简历/面经/策略）
└──────────────────────────┘
```

你需要准备：一个飞书账号（个人版即可，企业版更好）；本机后端已能启动（`uvicorn app.main:app --port 8000`）；多维表格不用手建，§2 直接复制模板。

**5 个值**（最终都填到配置页「飞书」分组，每个值从哪拿、长什么样）：

| 值 | 长什么样 | 从哪拿 |
|---|---|---|
| App ID | `cli_` 开头 | 开放平台 → 应用「凭证与基础信息」页（见 §1） |
| App Secret | 一串字母数字 | 同上，点「复制」（见 §1） |
| App Token | 地址栏 `/base/` 后的一串 | 打开**你的**多维表格副本看浏览器地址栏（见 §2） |
| 各表 Table ID | `tbl` 开头，**每张表各一个** | 地址栏 `table=` 后的一串（见 §2） |
| open_id / chat_id | `ou_` 开头（发给个人）/ `oc_` 开头（发到群） | 见 §8「两个 ID 怎么拿」 |

**3 处授权**（漏任何一处系统就不通；**生效时机各不相同**，这是新手最大的坑）：

| 授权 | 在哪做 | 什么时候做 | 什么时候生效 |
|---|---|---|---|
| ① 开放平台权限 | 应用「权限管理」 | 勾完权限**立刻去发布版本**（§4） | **不发布版本就完全不生效**——新手第一大死点 |
| ② 文档协作者 | 多维表格「分享」 | 复制副本后马上做（§2） | 即时生效；不加的话应用拿着 Token 也读不了表——第二大死点 |
| ③ 事件订阅 | 应用「事件与回调」 | 与权限同批做（§5） | 改完建议再发布一个版本 |

## 1. 创建飞书自建应用 → 拿 App ID + App Secret

1. 打开 [open.feishu.cn](https://open.feishu.cn) → 右上角「开发者后台」
2. 「创建企业自建应用」，随便起名（如 `求职助手`），图标随意
3. 创建完成后进入应用页面：
   - 左侧「**凭证与基础信息**」→ 复制 **App ID**（`cli_` 开头）和 **App Secret**
   - 先存好，§6 一起填进配置页

## 2. 复制多维表格模板 → 拿 App Token + 各表 Table ID + 加协作者

**推荐直接复制官方模板**（含全部 5 张数据表、57 个岗位字段、单选选项与视图配置，无需手建）：

1. 打开模板链接：[Auto-JobHunter 求职中枢模板](https://ucncdzmaddi9.feishu.cn/base/VfEwbBBNhaqzEBsK18oc665Qnkh) → 右上角「...」→「**保存副本**」到你自己的云空间，重命名为 `求职中枢`
   - 模板自带 5 张表：**岗位数据汇总表**（主链路）、**我的简历库**、**个人专属面经库**、**单篇面经情报库**、**面经高频题库**——每张表对应配置页哪个字段，见 §8 字典
   <details>
   <summary>不想用模板？也可以手动新建</summary>

   飞书 → 云文档 → 新建多维表格 → 右下角 `+` 新建数据表：至少建「岗位数据汇总表」一张（必需，字段按流水线需要自行添加），其余表按需。手动方式需要自己琢磨字段与选项，不推荐。
   </details>

2. **马上做授权②：把应用加为协作者**（即时生效）：
   - 打开该文档 → 右上角「分享」→ 添加协作者 → 搜索你的应用名（`求职助手`）→ 权限选「**可编辑**」
   - 不做这步，应用拿到 Token 也读不了文档

3. 拿 **App Token**：浏览器打开该文档，地址栏 `/base/` 后面的字符串
   （如 `https://xxx.feishu.cn/base/CFkBYourAppTokenPlaceholder?table=tblyYourTableIdPlaceholder` 中的 `CFkBYourAppTokenPlaceholder`）
4. 拿各表 **Table ID**：切换到对应表，地址栏 `table=` 后面的字符串（如 `tblyYourTableIdPlaceholder`），**每张表各自一个**，§6 一起填

## 3. 开启机器人能力

应用页面 → 左侧「**添加应用能力**」→ 勾选「**机器人**」→ 保存。

不做这步，机器人无法收发群消息。

## 4. 开通权限（关键，最容易漏"发布"）

应用页面 → 左侧「**权限管理**」→ 搜索并开通以下权限：

| 权限名 | 用途 |
|---|---|
| `im:message`（读取与发送单聊、群组消息） | 收群里 @机器人 的消息 + 回复 |
| `im:chat`（获取群组信息） | 列出机器人所在的群（配置页群下拉列表用） |
| `bitable:app` / `bitable:record`（读写） | 多维表格同步（岗位/简历/策略/偏好） |

> 💡 搜索权限名时直接搜 `im:message`、`bitable` 即可，把相关读写权限都勾上。

**⚠️ 最重要的一步：开通权限后必须「创建版本」并「发布」！**

应用页面 → 左侧「**版本管理与发布**」→ 创建版本 → 填写版本号和更新说明 → 提交发布（自建应用一般秒过/管理员秒批）。

> 飞书的权限/能力变更，**不发布版本就完全不生效**——这就是 §0 说的授权①生效时机。
> 判断方法：改完权限如果系统还是不通，先回来确认版本发过了没有。

## 5. 配置事件订阅（长连接，无需公网 IP）

应用页面 → 左侧「**事件与回调**」→「**事件配置**」：

1. 订阅方式选择「**使用长连接接收事件**」（不要选"请求地址"，那需要公网 URL）
2. 「添加事件」→ 搜索 `im.message.receive_v1`（接收消息 v2.0）→ 添加
3. 「添加事件」→ 搜索 `bitable_record_changed`（**多维表格记录变更**，drive.v1.file.bitable_record_changed）→ 添加
   —— 不订阅此事件系统也能用，但「在飞书表格里手改跟进状态 → 本地 5 分钟内自动感知」的反向同步会退化为纯定时刷新

> 改完事件配置后同样建议发布一个版本。

> ⚠️ **审批门禁的覆盖范围**：`FEISHU_APPROVER_OPEN_IDS` 白名单管控的是**卡片按钮**（放行/批准/召回/回收/发起评估等）与**精确审批词**（"放行/通过/批准/拒绝"等）。自然语言对话（如"帮我把这个岗位改成待投递"）由 ChatAgent 大模型判定执行，不做逐句鉴权——多人部署时请勿把机器人拉入不受信任的群。

## 6. 后端启动 + 页面填写 + 一键自检

```bash
cd backend
uvicorn app.main:app --port 8000
```

启动日志看到这行即长连接建立成功：

```
✅ 飞书 WebSocket 长连接已启动
```

然后：

1. 打开前端 →「策略实验室 → 系统底层配置」→「飞书」分组，把 §1/§2 拿到的值填齐 → **保存配置**
   （保存即时生效：若后端启动时凭证还没填，保存动作会自动用新凭证重连长连接，无需重启）
2. 点击「飞书」分组的「**检测连通性**」，预期 6 项全绿：
   - ✓ App ID / App Secret 已填写
   - ✓ 凭证有效（换取到访问令牌）
   - ✓ 多维表格文档可读
   - ✓ 数据表 ID 已配置且可读
   - ✓ 机器人能力与 IM 权限正常（已在群里）
   - ✓ WebSocket 长连接在线

   ❌ 哪项红了按提示修复后重测即可。

## 7. 把机器人拉入群 & 首次对话

1. 打开你想用来指挥的飞书群 → 群设置 →「群机器人」→ 添加机器人 → 选你的应用
2. 回到配置页下方「飞书聊天指令」区，把「接收群 Chat ID」选成这个群（战报推送用）
3. 在群里发送：

```
@求职助手 ping
```

收到 `🏓 pong` 即全链路打通 🎉。之后直接用自然语言指挥，例如：

- 「看看整体数据」/「发今天的日报」
- 「帮我找一下 字节 的 后端 岗」
- 「帮这个岗位评估一下」「把这条改成已投递」

全部指令话术见配置页「指令话术」按钮（话术清单由后端自动下发，永远和实际能力同步）。

## 8. 配置项字典：每个字段是什么、对应哪张表、去哪拿值

配置页「飞书」分组共 10 个字段，逐一对账（**"对应表"列 = 模板副本里的表名**，配置页显示名与表名不一致是故意的——字段名短，表名全）。注：配置页「飞书」分组**下方**的「接收群 Chat ID」下拉是独立控件（战报推送目标绑定用），不在这 10 项之内：

| 配置页显示名 | 配置键 | 对应模板表 / 值格式 | 干什么用 | 必要性 |
|---|---|---|---|---|
| App ID | `FEISHU_APP_ID` | `cli_` 开头 | 应用身份：换取访问令牌 + 建长连接 | **必需** |
| App Secret | `FEISHU_APP_SECRET` | 字母数字串 | 同上（与 App ID 配对） | **必需** |
| App Token | `FEISHU_APP_TOKEN` | 整个多维表格文档的 ID | 所有表读写的"根" | **必需** |
| 岗位总表 | `FEISHU_TABLE_ID_JOBS` | 「岗位数据汇总表」 | 主链路：抓取→清洗→评估→投递状态全部同步这张表 | **必需** |
| 简历库 | `FEISHU_TABLE_ID_RESUMES` | 「我的简历库」 | 评估/投递时取简历原文 | **必需** |
| 面试报告 | `FEISHU_TABLE_ID_INTERVIEW_REPORTS` | 「单篇面经情报库」 | 面经 copilot：按岗位标签检索单篇面经 → LLM 聚合情报（实验性） | 可选 |
| 面试汇总 | `FEISHU_TABLE_ID_INTERVIEW_SUMMARY` | 「面经高频题库」 | 面经 copilot 的高频题**聚合缓存表**（系统自动写入，勿手改；实验性） | 可选 |
| 真题库 | `FEISHU_TABLE_ID_INTERVIEW_REAL` | 「个人专属面经库」 | 面试训练营：真题练习、模拟面试记录的读写库；ChatAgent 面经问答也读它 | 可选 |
| 预警接收人 ID | `FEISHU_ALERT_RECEIVE_ID` | `ou_`（私聊你个人）或 `oc_`（发到群） | ①平台登录态失效时飞书告警你；②战报/日报的**兜底**接收目标（「接收群 Chat ID」已绑定时不走它） | 可选 |
| 审批人白名单 | `FEISHU_APPROVER_OPEN_IDS` | open_id（`ou_` 开头）逗号分隔；**空 = 全员可审批** | 卡片按钮（放行/批准/召回等）与精确审批词的鉴权，见 §5 覆盖范围说明 | 多人部署建议配 |

> 「已下架归档」表模板里没有也不需要：它是清理死链岗位的运维工具，需要时运行
> `python backend/scripts/offshelf_cleanup/offshelf.py create-archive` 即可按当前岗位表字段自动创建。

### 两个 ID 怎么拿（预警接收人 / 审批白名单）

**群 ID（`oc_` 开头）——最简单**：

- 把机器人拉进群后，配置页下方「接收群 Chat ID」下拉直接选中该群，那个值就是 `oc_` 开头的 chat_id；
- 或在群里 @机器人 说句话，白盒控制台（⌘J）日志里会出现 `[WS] 收到消息 | chat_id=oc_xxx…`，直接复制。

**个人 open_id（`ou_` 开头）——系统内零门槛法（推荐）**：

1. 先在「审批人白名单」随手填一个占位值（如 `ou_tmp`）→ 保存
2. 在群里**直接发送一条快捷审批词**（如「放行」）——任意时刻可用，不需要等系统先跑出战报卡片；也可以对任意战报/审批卡片点一个按钮，效果相同
3. 白盒控制台（⌘J）会出现一条拒绝日志：`[审批门禁] 文字快捷审批被拒绝（操作者=ou_你的真实ID）`（点按钮则显示 `卡片动作 … 被拒绝`）
4. 把真实的 `ou_` 值填回白名单，保存即可（这一来一回顺带验证了门禁真的在工作）

**个人 open_id——官方法**：开发者后台 → 你的应用 →「API 调试台」→ 调用「通过手机号或邮箱获取用户 ID」，传自己手机号拿 open_id（需额外开通通讯录读权限并发布版本，不如上面一招省事）。

> 单人群自用建议：预警接收人直接填群 `oc_`（和「接收群 Chat ID」同一个群即可），告警和战报都进同一个群，手机不用装第二个通知渠道。

## 9. 排错 FAQ（按死点频率排序）

| 现象 / 报错 | 死因 | 修复 |
|---|---|---|
| 权限改了但完全没反应 | **应用没发布版本** | 「版本管理与发布」→ 创建版本 → 发布 |
| 换 token 失败 `invalid app_secret` | Secret 填错/带空格 | 「凭证与基础信息」重新复制 |
| 读表格 403 / permission denied | **应用没加为文档协作者** | 文档「分享」→ 应用加为可编辑协作者 |
| 读表格 404 / not found | App Token 填错 | 地址栏 `/base/` 后的字符串重新复制 |
| 表读取失败 `table not found` | Table ID 填错 | 对应表地址栏 `table=` 后的字符串重新复制 |
| 群列表拉不到 / 机器人收不到消息 | 缺机器人能力或 `im:message` 权限 | 「添加应用能力」勾机器人 + 权限管理开 `im:message` + 发布版本 |
| 长连接起不来：`无在线长连接` 提示 | 事件订阅没切「长连接」 | 「事件与回调 → 事件配置」切到「使用长连接接收事件」 |
| 长连接起不来：日志显示未配置凭证 | App ID/Secret 没填 | 配置页「飞书」分组填写并保存（保存会自动重连） |
| 机器人拉不进群 | 应用未发布 / 未开机器人能力 | 发布版本 + 开启机器人能力后重试 |
| 在群里发 ping 没反应 | 机器人不在群里 / 没发 `@机器人` | 确认群机器人里有应用；消息必须 @机器人 |
| 点审批按钮全被拒绝 `⛔ 此操作需要审批权限` | 白名单里是占位 ID / 填了别人的 open_id | 按 §8「个人 open_id 零门槛法」捞真实 ID 填回 |
| 配置页保存后部分功能没变 | 个别模块需重启才读取新值 | 重启后端（绝大多数配置已即时生效，保存时的提示会说明） |

> 通用的排错顺序：先点「检测连通性」看哪一项红 → 按提示修复 → 重测；检测全绿但聊天不通时，看后端启动日志里 `[WS]` 开头的行。

## 10. 配置的优先级与生效规则

系统有两层配置源，**页面保存的值（`backend/common/data/settings.json`）永远优先于 `.env`**：

| 配置方式 | 优先级 | 生效时机 |
|---|---|---|
| 配置页保存（settings.json） | 高 | 保存后即时生效（飞书长连接自动重连、ChatAgent 自动重建） |
| `.env`（backend/.env） | 低 | 启动时读取 |

排错小技巧：如果页面填了值但行为像旧配置，检查 `backend/common/data/settings.json` 里是否有旧值残留（它是历史保存的累积）。页面配置值可随时清除：**悬停配置字段 → 点「清除」→ 保存**，即回落到 `.env` 的值（未在 .env 配置则为未配置状态）。
